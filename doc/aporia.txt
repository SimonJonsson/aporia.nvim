INTRODUCTION                                                        *aporia*

Aporia is a Neovim plugin for writing code with a large language model while
staying fully locked in: you write every line, the model works around you.
It has two modes, each with its own keys, prompt and conversation:

  assist    augments you as far as possible short of writing your code:
            explains, locates APIs, diagnoses errors, reviews, plans.
            Keys on <leader>a.                          |aporia-keymaps|
  teach     named exercises against known learning traps; asks questions
            instead of answering them. Keys on <leader>t.  |aporia-traps|

Design guarantees:
  • You write the code - no code path edits your buffers, and neither mode
    hands you a solution you could paste in
  • No unprompted output - nothing appears without a keypress
  • Explicit mode - you always know whether you are in assist or teach
  • Verification paths - every claim carries a doc you can check

==============================================================================
SETUP                                                         *aporia-setup*

>lua
  {
    dir = "~/Repos/aporia.nvim",
    cmd = "Aporia",
    keys = { "<leader>tq", "<leader>th", "<leader>tr",
             "<leader>ts", "<leader>tc", "<leader>tl",
             "<leader>tt", "<leader>at", "<leader>aa", "<leader>ab" },
    opts = {
      provider = "baseten",
      providers = {
        baseten = {
          base_url = "https://inference.baseten.co/v1",
          model = "your-model-id",
          api_key_env = "BASETEN_API_KEY",
        },
      },
    },
  }
<

==============================================================================
COMMANDS                                                    *aporia-commands*

:Aporia [sub]                                                 *:Aporia*
    Without argument: toggle the chat window.
    Subcommands: toggle, assist, teach, reset, resume, delete-all-sessions,
    add, addbuffer, question, hint, reframe, steps, rootcause, log. `assist`
    and `teach` open the chat in that mode; `reset` wipes both conversations;
    `resume` picks a saved conversation of the current mode to continue;
    `delete-all-sessions` removes the project's saved sessions after asking.

==============================================================================
KEYMAPS                                                      *aporia-keymaps*

<leader>tq     Question check (Forming)
<leader>th     Hint ladder (Dislodging)
<leader>tr     Reframe (Assumption)
<leader>ts     Step audit (Location)
<leader>tc     Root-cause challenge (Achievement)
<leader>tl     Log what I learned (Progression)
<leader>tt     Toggle chat window in teach mode
<leader>at     Toggle chat window in assist mode
<leader>aa     Stage visual selection as context
<leader>ab     Stage whole buffer as context

Inside the chat:
<CR>           Send the input window's contents
<C-j>          Newline while composing (in the input window)
q              Hide the chat (works in every window)
x              Clear the current mode's conversation
/              (input, start of line) open the command menu: <C-n>/<C-p>
               move, <C-y> accepts, <C-e> dismisses, <CR> sends as typed

Slash commands, typed into the input and sent with <CR>:   *aporia-slash*
/new           Fresh conversation in the current mode
/resume        Pick a saved conversation of the current mode and continue it
/assist        Switch to assist mode
/teach         Switch to teach mode
/reset         Wipe both conversations and staged context
/delete-all-sessions
               Delete every saved session in this project (asks first)
//text         Send "/text" as an ordinary message
d              Unstage the item under the cursor (staged context box)
Esc            Leave insert mode in the input window

The sidebar is three floating boxes: read-only chat history on top, the
staged-context box in the middle (only shown when something is staged),
and the input window at the bottom. Only the input window is editable.
The input hint starts with the active mode, and the borders link to
AporiaBorderAssist or AporiaBorderTeach.

==============================================================================
TRAPS                                                          *aporia-traps*

Each trap switches the chat to teach mode.

Forming      Right question, wrong answer         <leader>tq
Dislodging   Stuck in a rut                       <leader>th
Assumption   Solving the wrong problem            <leader>tr
Location     Skipping critical steps              <leader>ts
Achievement  Fixing instead of root-cause         <leader>tc
Progression  Falling behind without noticing      <leader>tl

The AI-introduced traps (Interruption, Mislead) are handled structurally:
the plugin has no completion source, no auto-trigger, and every fetch of
external documentation passes through the gate configured in |aporia-config|.

==============================================================================
CONFIG                                                         *aporia-config*

API keys are resolved per provider, in order:
  1. api_key      literal key (only sensible for local servers)
  2. api_key_env  environment variable, e.g. BASETEN_API_KEY
  3. api_key_cmd  shell command whose stdout is the key, e.g.
                  "secret-tool lookup service baseten"

To store a key in the GNOME keyring (survives GUI-launched nvim):
>
  secret-tool store --label=aporia service baseten api_key
  # paste the key, Ctrl-D to finish
<

fetch.mode     "links" | "confirm" | "auto" (default "confirm")
fetch.max_fetches_per_turn  (default 2)
context.padding             lines of surrounding context staged with a
                            selection (default 15)
context.max_lines           truncation cap per staged block (default 200)
log_file                    learning log path (default ~/notes/learning.md)
backend.enabled             use the Rust backend when built (default true)
backend.cmd                 backend binary; default the newest of
                            backend/target/{release,debug}/aporia
backend.max_rounds          model calls per reply, the last without tools
                            (default 8)

==============================================================================
PROJECT TOOLS                                                  *aporia-tools*

With the backend built (`make backend` in the plugin directory), assist mode
can read the project before answering: `list_files`, `grep` and
`read_file`. Each step shows under the reply as it runs. The tools are
read-only, stay inside the project root, skip .git/ and .aporia/, and refuse
files git ignores. Open buffers are read with unsaved edits. Teach mode gets
no tools. |:checkhealth| aporia reports whether the backend answers.
